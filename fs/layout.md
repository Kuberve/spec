# Файловая система Kuberve: корневой layout

## Общая структура

Корень FAT32 (и будущей KuberveFS) организован по принципу
"разделение по назначению", а не по Unix-истории (`/bin`, `/etc`,
`/usr` смешивают системные и пользовательские файлы).

```
/
├── system/         системные компоненты (bin, lib, conf, boot)
├── apps/           общие установленные приложения (app bundles)
├── users/          данные пользователей (per-uid)
└── mounts/         точки монтирования внешних ФС
```

## system/

Системные компоненты, установленные с ОС. Пользователь их не
редактирует, пакетный менеджер может обновлять целиком.

```
/system/
├── bin/            исполняемые файлы (init, uart, shell, ...)
├── lib/            общие библиотеки (пока пусто)
├── conf/           системные конфиги (init.conf, ...)
└── boot/           файлы для будущего загрузчика (initrd, DTB, modules)
```

**Не хранится здесь:** kernel image. Kernel грузится загрузчиком
(U-Boot / QEMU `-kernel`) **до** монтирования ФС. В `/system/boot/`
будут initrd, Device Tree Blobs, kernel modules — но не сам kernel.

**Правило:** ELF-файлы без расширения. `/system/bin/init`, не
`init.elf`. FAT32 8.3 это выдерживает (`INIT    ` + 3 пробела);
`find_entry` нормализует имена case-insensitive.

## apps/

Общие установленные приложения. Каждое приложение = **app bundle**:
директория с бинарём, библиотеками, конфигами и данными.

```
/apps/
├── firefox/
│   ├── bin/firefox
│   ├── lib/          (зависимости)
│   ├── conf/         (конфиги приложения)
│   └── data/         (иконки, ресурсы, ...)
└── nano/
    └── bin/nano
```

**Правило:** приложение **изолировано в своей папке**. Нет глобального
`/apps/bin/` где лежат все бинари — пакетный менеджер ставит и
удаляет app bundle целиком (Flatpak/NixOS-подобная модель).

**Установка:** `/apps/<name>/` создаётся атомарно (extract из .kvpkg).
**Удаление:** `rm -rf /apps/<name>/`.

## users/

Данные пользователей, разделённые по uid (0 = root, 1+ = обычные).

```
/users/
├── 0/              root
│   ├── apps/       (локальные приложения, установленные root'ом)
│   ├── conf/       (пользовательские конфиги)
│   ├── Downloads/
│   └── Pictures/
└── 1/              первый обычный пользователь
    └── ...
```

**Правило:** uid **числом** (0, 1, ...), не именем (`alice`, `bob`).
Имена — через `/system/conf/passwd` (аналог Unix), uid первичен.
Так избегаем коллизий имён и совпадает с будущим `chown`.

**Приватные приложения** живут в `/users/<uid>/apps/<name>/` — та же
структура app bundle.

## mounts/

Точки монтирования для внешних ФС (USB, SD, сетевые шары).

```
/mounts/
├── usb0/           (автоматически при подключении)
└── net-share/      (NFS/SMB, позже)
```

**Правило:** монтирование **не в корень**, а в `/mounts/<name>/`.
Корень остаётся read-mostly, system + apps + users не смешиваются
с внешними данными.

## Специальные файлы

| Путь | Назначение |
|---|---|
| `/system/conf/init.conf` | список сервисов для init |
| `/system/bin/init` | PID 1, читает init.conf |
| `/system/bin/uart` | uart_server (пока единственный сервис) |

## Формат init.conf

Line-based, простой парсер:

```
# комментарии через #
/system/bin/uart  2
# /system/bin/shell  1
```

**Формат:** `<абсолютный путь> <priority>` через whitespace.
- `#` — комментарий (вся строка)
- Пустые строки игнорируются
- `priority` — 0..255, как в `spawn_el0`
- Путь начинается с `/`

**Почему line-based:** парсер — ~20 строк Rust, без зависимостей.
Расширяется позже (env vars, args) через `key=value` в следующих
колонках.

## FAT32 8.3 ограничения (текущий milestone)

FAT32 в QEMU `nvme.img` — **8.3 имена**:
- Имя до 8 символов + расширение до 3
- Case-insensitive (нормализация в UPPER)
- Нет `:` `<` `>` `"` `/` `\` `|` `?` `*`
- Нет `.` в начале

**Последствия:**
- `conf` (не `conf.d`) — 8.3 влезает как имя `CONF`
- `Downloads`, `Pictures` — обрежутся до 8 символов
- ELF без суффикса — ок
- uid числом — ок, `0` влезает

**Позже** (Phase 3, KuberveFS) — имена любой длины, unicode,
case-sensitive. FAT32 останется для внешних SD/USB.
